# Что оставить на следующий этап

- Проверить реальные региональные тарифы и правовые основания работы сервиса; заполнить сведения оператора и политику. Это требует владельца и достоверных источников.
- Пройти ручной приёмочный сценарий с отдельным тестовым Telegram-ботом, группой и форумной темой; проверить Windows на реальной машине.
- Подключить официальную проверку адреса только при наличии договора/API; текущий бот ничего не обещает о технической возможности.
- Добавить отдельные структурированные денежные поля и редактор тарифов при реальной потребности; сейчас цены/пакеты редактируются в JSON-описании без выдуманной нормализации.
- Более детальная ролевая модель (назначенный сотрудник, руководитель), фильтры/пагинация списка CRM и статистики; текущие 20 карточек и top-15 срезов ограничены сознательно.
- Управляемый регламент удаления сообщений/резервных копий и автоматизированные отчёты о выполнении запросов удаления. Локальное обезличивание не удаляет все внешние копии.
- Мониторинг проблем доставки и ротация журналов без ПДн; при очень большой базе — потоковый экспорт вместо чтения всех строк в память.
- CI для Python 3.12 / Windows и Linux. Тесты уже запускаются без Telegram и внешних сервисов.

Redis, PostgreSQL, Docker, платные сервисы для текущей задачи не требуются.
