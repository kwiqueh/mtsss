- `python -m unittest discover -s tests -v`: **29 тестов, OK**, без пропусков. Последний полный прогон также выполнен сохранённым install_script.

- `ruff check --select F,E9 .` (ruff 0.17.2): **All checks passed**. Проверены неопределённые имена, неиспользуемые импорты и синтаксические ошибки. Совместимые импорты помощников из bot.py сохранены явно.
- `git diff --check`: успешно.
- Повторное выполнение установки с закреплёнными версиями и тестами: успешно, исходные данные не создаются.
- `python run.py --check-config` без реальных настроек: ожидаемо завершился с кодом 1 и сообщением об отсутствующем токене. Валидация корректных и некорректных настроек проверена на синтетических значениях в тестах.

## Покрытые сценарии

1. Чтение файла с BOM/кавычками, приоритет окружения, проверка обязательных настроек и передача CRM/темы/интервала, маскирование логов.
2. Создание заявки, чтение после повторного init_db, сохранность SQLite и целостность схемы.
3. Невалидные телефоны/имена/услуги/ключи формы не записываются.
4. 16 одновременных подтверждений одной формы дают одну запись; новая идентичная форма за 5 минут не дублируется, другая услуга сохраняется отдельно.
5. 20 параллельных пользователей создают 20 записей; атомарные обновления FSM не теряют поля.
6. Назначение сотрудника, история старого статуса, закрытая заявка не берётся повторно; проверка конверсии по сохранённым данным.
7. Запрет управления постороннему/из другого чата; запрет экспорта в группу.
8. Успешная CRM-доставка через имитатор, неопределённая сетевая ошибка, резервирование и ручной повтор после проверки.
9. Напоминание один раз, сохранность отметки после повторного открытия базы, запрет после завершения/отмены, FOLLOWUP_MINUTES=0, ошибка Forbidden без повторного спама.
10. CSV: UTF-8 BOM, пустая база, обязательные столбцы, защита формул после пробелов/управляющих символов, запрет случайной перезаписи; read-only подключение не разрешает DELETE.
11. Миграция старой схемы с записью и резервной копией, повторный запуск; неподдерживаемая схема откатывается без потери строки.
12. Первое рекламное касание сохраняется при новых /start, невалидные метки отвергаются; сохранённые источник/кампания проверены SQL-запросом.
13. Запрос удаления, dry-run и явное обезличивание контактов с сохранением строки заявки.
14. Настоящий Dispatcher aiogram + SQLiteStorage + FakeSession: две формы консультации разных пользователей, неверный ввод, старое подтверждение, параллельные клики; затем полный выбор домашнего тарифа с вариантом/адресом/возвратом/подтверждением и проверкой закрытой сессии.
15. Все ссылки каталога, ограничения callback_data до 64 байт, отключённый тариф и длина карточек; блокировка второго процесса на той же базе.

## Не проверено вживую

- Telegram getMe, polling, реальные сообщения клиенту, права CRM-группы/темы и настоящая доставка документов: токен и Telegram ID не предоставлены. На этапе настройки HTTPS api.telegram.org отвечал запретом CONNECT 403; добавление домена сохранено в черновике, применение к работающей машине не подтверждено.
- Реальная Windows: нет Windows-машины. Описана установка Python 3.12, зависимости/OS-блокировка предусматривают Windows, но это не результат запуска на Windows.
- Реальная база пользователя: отсутствует. Проверена миграция временной базы с прежней минимальной схемой; перед рабочим обновлением нужна проверка на приватной копии.
- Актуальные цены/регион/правовой статус: внешнего подтверждения нет. Исходные цены сохранены, уведомление о необходимости проверки добавлено.
- Реальная политика/оператор, права и сроки хранения: должен задать владелец. Процедура обезличивания не удаляет автоматически сообщения Telegram, старые выгрузки и резервные копии.
