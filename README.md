# МТС Экспресс

Существующий Telegram-бот на Python / aiogram 3, с локальной SQLite, CRM-карточками и CSV. Название проекта не подтверждает официальный статус представителя МТС. Реальные токены, клиентская база и выгрузки в репозиторий не входят.

## Запуск в Windows (PowerShell)

Нужен Python 3.12 с python.org и Git. Откройте PowerShell в каталоге проекта:

```powershell
git clone https://github.com/kwiqueh/mtsss.git
cd mtsss
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
Copy-Item bot.env.example bot.env
notepad bot.env
.\.venv\Scripts\python.exe run.py --check-config
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe run.py
```

Если каталог уже существует, используйте его; повторно клонировать проект не требуется. Активация venv не обязательна, изменение ExecutionPolicy не нужно. `bot.env` заполняется владельцем локально; настоящий токен не отправляйте в сообщения, Git или логи. При первом запуске основной администратор должен открыть личный чат с ботом и нажать Start. Для группы добавьте бота в CRM-группу и выдайте право отправлять сообщения; для темы включите темы и укажите её ID.

Для Linux команды аналогичны: `python3 -m venv .venv`, затем `.venv/bin/python ...`. Проверенная облачная машина — Linux, Python 3.12.14; работа на Windows описана, но Windows в этой среде не запускалась. `tzdata` закреплён для Windows, где системная база часовых поясов обычно отсутствует.

## Настройки

Переменные процесса имеют приоритет над `bot.env`. Файл понимает UTF-8/BOM, старый cp1251, парные кавычки и строки комментариев. Значения не исполняются; это не shell-скрипт. Inline-комментарии после значений не поддерживаются. Ошибка настройки завершает запуск с кодом 1 без печати токена.

| Настройка | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Обязательный реальный токен BotFather; в коде нет запасного токена. |
| `TELEGRAM_ADMIN_ID` | Обязательный положительный Telegram ID владельца. Встроенного администратора нет. |
| `ADMIN_IDS` | Необязательные дополнительные администраторы, ID через запятую. |
| `MANAGER_IDS` | Сотрудники CRM, ID через запятую; администраторы включаются автоматически. |
| `CRM_CHAT_ID` | Числовой ID CRM. Пустое значение — личный чат основного администратора; для группы обычно отрицательный ID. |
| `CRM_THREAD_ID` | Необязательный положительный ID темы CRM-группы. |
| `FOLLOWUP_MINUTES` | 0 — отключить; 1–10080 — интервал до единственного напоминания о незавершённом выборе. По умолчанию 25. |
| `DB_PATH` | Постоянный файл SQLite; относительный путь считается от каталога проекта. По умолчанию `leads.db`. |
| `PRIVACY_POLICY_URL` | Обязательная HTTPS-ссылка на политику фактического оператора данных. |
| `PERSONAL_DATA_OPERATOR` | Обязательное имя/наименование фактического оператора. Не подставляйте ПАО «МТС» без правового основания. |
| `POLICY_VERSION` | Версия согласия, сохраняемая с заявкой. По умолчанию `2026-01`. |
| `RETENTION_DAYS` | Срок хранения для процедуры обезличивания; по умолчанию 180. Не юридическая рекомендация: оператор устанавливает обоснованный срок. |
| `TELEGRAM_PROXY` | Необязательный HTTP/SOCKS4/SOCKS5-прокси. Аутентификационные данные не выводятся в лог. |
| `AGENT_NAME` | Отображаемое имя сервиса/консультанта. |

TLS-проверка включена. `HTTPS_PROXY` сам по себе не является настройкой прокси aiogram: при необходимости задайте `TELEGRAM_PROXY`. В облачной среде также нужен разрешённый HTTPS-доступ к `api.telegram.org`. Если секрет-посредник подставляет placeholder вместо токена, он не пройдёт строгую проверку BotFather-формата; требуется безопасное предоставление реального значения переменной процесса или локального `bot.env`, без помещения его в сохранённые инструкции.

## Клиентский сценарий

`/start` или `/menu`: подбор услуги либо консультация. Для консультации достаточно имени, мобильного телефона РФ и удобного времени звонка. Адрес спрашивается только для домашних услуг/спутникового ТВ/интернета в офис, без квартиры. Клиент видит данные и политику перед отправкой; рекламное согласие по умолчанию выключено.

`/back` возвращает к вводу данных, `/cancel` отменяет форму и напоминания. Есть кнопки назад и главного меню. Старые кнопки не отправляют завершённую форму повторно. Параллельные события одного пользователя изолированы. Ключ формы сохраняется в FSM/SQLite, поэтому повтор после перезапуска не создаёт новую заявку. Новая идентичная форма того же пользователя в течение 5 минут также возвращает номер существующей заявки. Разные услуги и разные пользователи не объединяются; повторный клиент с новой заявкой получает совместимый статус `повторная`.

Старые незавершённые формы до обновления не имеют ключа отправки: их нужно начать заново через `/menu`. Существующие сохранённые заявки остаются доступными.

## CRM

- `/leads` — последние 20 заявок, `/lead ID` — карточка в настроенном CRM-чате.
- Кнопки: взять в работу, связались, назначено, подключено, отказ, не удалось связаться, заметка. Управление доступно только заданным сотрудникам в CRM-чате. Все сотрудники из списка могут менять статусы; это общая рабочая очередь, без разграничения «только назначенный менеджер».
- `/stats` — общее число, сегодня, статусы, агенты/домовые метки; отдельное сообщение показывает категории, источники, кампании, даты и доставку. Срезы ограничены наиболее частыми 10–15 значениями, общий итог и конверсия считаются по всей базе. Конверсия = число заявок со статусом `подключено` / число всех заявок, не конверсия уникальных пользователей.
- `/export` — только администратору и только в личном чате. Отправка с `protect_content`, временный серверный CSV удаляется в `finally`. Ограничение Telegram не заменяет контроль доступа к устройствам сотрудников.
- `/delivery` — последние проблемные доставки. `ошибка` повторяется с ограничением попыток и задержкой; `недоступно` требует исправить права/параметры CRM; `проверить` означает неопределённый результат или прерванную отправку.
- После проверки CRM администратор может в личном чате выполнить `/retry_delivery ID CONFIRM`. Повтор карточки возможен, если Telegram уже доставил предыдущую. Эта команда не создаёт новую клиентскую заявку.

История статусов сохраняет старое значение в той же транзакции. Старые статусы `связались`, `назначено`, `не дозвонились`, `повторная` поддерживаются. Взять уже закрытую заявку кнопкой назначения нельзя; уполномоченный сотрудник может осознанно изменить статус карточки.

## Рекламные источники

Ссылки вида `https://t.me/<имя_бота>?start=vk_campaign1`, `tg_channel1`, `ads_banner1`, `qr_house1`. Ввод после `start=`: 1–64 символа ASCII из `A-Z a-z 0-9 _ -`. Префикс до первого `_` задаёт источник, остаток — кампанию. Поддерживаются `vk`, `tg`, `telegram`, `ads`, `qr`, `direct`; неизвестные или невалидные метки считаются прямыми переходами. Старые `alex_dom12`, `sasha`, `sergey_dom12` сохранены.

Атрибуция — **первое касание**, включая первый прямой переход. Последующие `/start` не перезаписывают источник. Нельзя помещать в рекламные метки телефоны, имена или другие персональные данные. В старых записях неизвестная категория остаётся `unknown`; бот не угадывает её по названию тарифа. Старые известные реферальные метки переносятся в источник/кампанию без изменения записей.

## Тарифы

Все 30 исходных карточек и пять категорий вынесены в `tariff_data.json`; клавиатуры и загрузка находятся в `tariffs.py`. Стоимости не выдумывались и не подтверждались у МТС. Убраны противоречивые проценты скидки в нескольких описаниях и обещание 100% спутникового сигнала; исходные цены сохранены.

Карточка: `title`, `description` (содержит действующие цены и пакеты), `category`, `region`, `verified_on` (ISO-дата реальной проверки), `active`, `conditions`, `price_note`, `speed_or_allowance`. Пустой `region` / `verified_on` отображается как неподтверждённый. Стоимость меняйте в `description`; дополнительные условия — в `conditions` / `price_note`. Не указывайте противоречивые значения. Кнопки вариантов используют названия карточек, а не отдельные копии цен из каталога. Ключи тарифов сохраняйте для совместимости; временно закрытое предложение отключайте через `active: false`.

После редактирования JSON выполните тесты и перезапустите процесс. Загрузчик проверяет ссылки и основные поля. До публикации владелец должен сверить тарифы, регион и условия с действующим источником оператора. Проверки адреса через официальную систему здесь нет.

## Напоминания и доставка

Напоминание относится к незавершённому **выбору услуги**, а не к закрытой CRM-заявке. Каждый шаг обновляет активность; ввод имени/телефона, отмена и завершение исключаются из очереди. Отметка в SQLite ставится атомарно **до** запроса к Telegram, с повторной проверкой активности. Перезапуск не сбрасывает её. Ошибка доставки такого напоминания не приводит к навязчивым повторам; при сбое напоминание может не дойти. Новый явно начатый сценарий снова допускает одно напоминание.

Для CRM отправки SQLite резервирует заявку до запроса. При неопределённом сетевом результате автоматическая пересылка выключается: Telegram API не даёт ключа идемпотентности для `sendMessage`. Утрата ответа не должна порождать бесконечные дубли. Запускайте один процесс на одну базу; OS-блокировка в `run.py` предотвращает второй процесс на том же узле. SQLite по сети/несколько машин с одним DB-файлом не поддерживаются.

## Выгрузка без Telegram

```powershell
.\.venv\Scripts\python.exe export_leads.py leads.db --output report.csv
```

База открывается read-only. Пустая база со схемой выгружается с заголовком. UTF-8 BOM, `;`, кавычки CSV; формулы и формулы после пробельных символов экранируются апострофом. CSV создаётся с правами 0600 на POSIX; в Windows ограничьте доступ NTFS ACL. Существующая выгрузка сохраняется, пока явно не указан `--overwrite`. Наличие локального доступа к файлу базы даёт доступ к данным: CLI не является отдельным сервером авторизации.

## Безопасное обновление

См. [docs/UPDATE.md](docs/UPDATE.md). Остановите старый процесс; не копируйте один `leads.db` от работающего бота без WAL. Новая версия автоматически делает согласованную резервную копию существующей базы через SQLite backup API перед первой миграцией. Дополнительные столбцы/индексы создаются транзакционно, старые строки не удаляются. Неизвестная схема или версия останавливает запуск. Запуск миграции рекомендуется сначала проверить на приватной копии.

## Персональные данные и обслуживание

`/delete_me` регистрирует запрос оператора и прекращает сценарий/напоминания. Это **не** обещание автоматического удаления всех копий. Остановив бота:

```powershell
.\.venv\Scripts\python.exe maintenance.py requests
.\.venv\Scripts\python.exe maintenance.py privacy
# После проверки срока, запросов и правил оператора:
.\.venv\Scripts\python.exe maintenance.py privacy --apply
```

Без `--apply` изменений нет. С `--apply` создаётся резервная копия, затем обезличиваются контакты, адрес, имя, заметка и пользовательский ID старых заявок/заявок с запросами удаления. Сами заявки и бизнес-статистика сохраняются. Удаляются связанные заметки активности, старые FSM/события/атрибуция. Очистка не запускается сама: настройте регламент и контролируйте выполнение. Новые заявки пользователя после обработки запроса обрабатываются по новому согласию.

Отдельно оператор должен удалить/ограничить копии в CRM-чатах, скачанные CSV, резервные копии и журналы. Резервные копии содержат исходные ПДн; храните их в защищённом каталоге с обоснованным сроком. База и CSV не шифруются самим ботом: используйте шифрование диска/BitLocker и ограничьте доступ к каталогу. Логи не содержат текстов клиентских сообщений; обработчик логов маскирует токены/URL/телефоны и скрывает payload исключений.
